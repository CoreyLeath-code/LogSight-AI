# Database timeout response

1. Confirm the error-rate increase and affected service in the normalized log stream.
2. Correlate the event fingerprint with database connection, latency, and saturation telemetry.
3. Preserve the incident timeline and request owner approval before changing connection-pool or failover settings.
4. Record the runbook version and repository revision used for the decision.
